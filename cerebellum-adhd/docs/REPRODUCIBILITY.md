# 复现与方法边界

## 软件验证与科学复现

`requirements.txt` 固定直接依赖版本，参考解释器为 Python 3.12。`requirements-paper.txt` 另安装旧版默认分析所需的 SHAP。GitHub Actions 在 Ubuntu/Python 3.12 上配置合成测试、六个入口的 `--help` 检查和发布包生成；实际 CI 状态应以仓库运行记录为准。

公开测试验证字段分组、公式、训练折预处理、常模拟合范围、概率输出、融合和五分类器消融的文件输出，不依赖任何真实受试者记录。合成输入含人为设定的类别效应，测试通过或示例 AUC 较高都不构成真实数据性能复现。

本次整理的本地检查（2026-10-23，Windows / Python 3.12.14）：依赖一致性检查通过；29 项 unittest 全部通过；六个入口的导入和 `--help` 通过；240 行合成数据上的五分类器 × 三视图 `smoke` 命令行实验成功完成。未重新运行真实队列上的完整论文分析、全部开发实验或 SHAP 出图流程。

完整论文复现还需要获授权的相同输入特征表、样本排除规则、标签编码和实验设置。原始数据的获取途径与再分发许可目前没有足够项目说明，故这里不提供未经核实的下载链接。Windows 本地验证不能替代 Linux/macOS 的实际执行，随机种子也不能保证不同 CPU、操作系统和底层库的结果逐位相同。

## 选择与验证范围

| 入口 | 需要保留的解释边界 |
| --- | --- |
| `ADHD_c.py` | 模型比较、全样本特征消融及参数开发后，再评估锁定分析；该队列参与开发 |
| `cereb_adhd_screen.py` | 包含训练折内的预处理和融合组件，但锁定的论文特征来源于全样本开发 |
| `cereb_adhd_optimization.py` | 在输入队列上开发特征集、参数和融合权重，再固定配置进行重复验证 |
| `cereb_adhd_v2.py` | 特征面板、稳定性选择及模型/融合开发使用同一输入队列 |
| `cerebnorm_adhd_screen.py` | 常模参考只用当前训练分区的对照拟合，但模型与融合配置在同一队列开发 |
| `cerebnorm_five_model_ablation.py` | 常模和预处理位于训练分区内；5 个脑特征此前已在全队列选定 |

这些设计应称为**探索性、选择后的内部验证**。训练折内拟合常模或预处理可以控制该环节的数据使用范围，不能消除上游全队列特征/参数选择带来的偏差。不同随机种子的划分也不等于独立队列。独立性能估计需要在预先隔离的测试集或外部队列上验证，或将整个开发与选择流程纳入外层训练分区。

旧版置换检验固定已选特征与模型，并未在每次标签置换后重跑完整搜索，因此不能据此宣称整个开发流程通过无偏的置换检验。`0.750` 是代码中的探索目标，不是发布时保证的性能。

## 指标口径

主要指标是 ROC-AUC，另报告平衡准确率、敏感度、特异度、F1 和平均精确率等，具体随入口而异。重复交叉验证将每位受试者的折外概率按其被预测次数汇总，再计算汇总 AUC；`mean_fold_AUC` 是各折 AUC 的均值，两者不是同一个统计量。

bootstrap 差值是对汇总折外预测进行受试者层面的重采样，未重跑开发、拟合和划分，也未量化全部模型选择不确定性。它不能直接解释为独立临床试验的效果区间。v2 的灰区分析仅是选择性分析；五模型特征消融不使用拒绝选项。

## 参数与结果留存

优先先运行 `fast/smoke`，确认字段和环境，再启动 `full`。保留每次输出的 `run_config.json`、命令、依赖版本和环境信息，使用新的输出目录避免覆盖前次实验。原始 `ADHD_c.py` 的论文开关和计算次数在文件顶部；其他入口的模式由各自 `RunMode/ExperimentMode` 定义，不能仅凭模式名称认定不同脚本使用了相同搜索预算。

真实数据上的 `oof_predictions.csv`、逐人模型解释和其他个体级文件应留在受控位置。当前默认忽略这些输出；发布汇总表也应先确认数据授权。仓库整理只改善可移植性、说明和测试，不重新证明已有论文结论。
